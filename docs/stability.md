# Stability: the public API

From **1.0.0**, the things listed here are stille-hunter's public API. They
change only in the ways [Semantic Versioning](https://semver.org/) allows, and
tests in CI hold them in place (`tests/test_compat.py`).

## What is covered

**The ledger format** — every field and meaning in
[ledger-format.md](ledger-format.md), in JSONL and CSV.

- Every 1.x release reads every ledger written by **0.1.0 or later**. CI
  loads real ledgers generated by each earlier release
  (`tests/compat/ledgers/<version>/`) and checks they still load, keep their
  markers, and work with `inbox` and `ledger`.
- New fields may be added in a minor release. Readers - this tool, your
  console, your scripts - must ignore fields they do not know.

**The plugin contracts** — what a canary type or a check source may rely on:

| name | where | contract |
|---|---|---|
| `CanaryType` | `stille_hunter.generate` | `name`, `description`, `add_arguments(parser)`, `generate(args, count)` yielding records with `record_id`, optional `_detect` and `_ledger` |
| `register_type`, `new_token`, `weighted_choice` | `stille_hunter.generate` | register a type; a 6-hex canary token; a weighted pick |
| `CheckSource` | `stille_hunter.check` | `name`, `supports`, `__init__(**config)` setting `config`, `stats`, `progress`; `available()`; `check(canaries)` yielding `Hit`s |
| `register` | `stille_hunter.check` | register a source |
| `Canary`, `Hit`, `SourceResult` | `stille_hunter.check` | their fields; `Canary.tokens()`; `Hit.to_dict()` keys |
| `load_ledger`, `run_check` | `stille_hunter.check` | their parameters and return values |
| entry-point groups | packaging | `stille_hunter.types`, `stille_hunter.sources` |

The plugin guide ([plugin-guide.md](plugin-guide.md)) explains each of them.

**The command line** — the commands `generate`, `check`, `inbox`, `history`
and `ledger list | retire | rotate`, their documented options, and the exit
codes of `check` and `inbox`: `0` clean, `1` something found, `2` usage error.

**Machine-readable output** — the keys of the JSON a consumer reads:

- `check --out` hit rows (`Hit.to_dict()` without guarantees on `detail`);
- `check --report run.json`;
- `check --history` lines (they carry `"schema": 1`);
- `history --json` and `ledger list --json`.

**The config file** — the sections a source reads under its own name, and
`notify` and `inbox`.

## What is not covered

- Anything whose name starts with `_`, and modules or functions not listed
  above.
- Human-readable output: the wording of what commands print, and the HTML
  report's layout. Parse the JSON instead.
- The generated data itself: name pools, address formats, domain mixes and
  their weights improve between releases.
- Proprietary sources that plug into the same contract; they are versioned on
  their own.

## How changes are versioned

| change | version |
|---|---|
| a bug fix, a doc fix | patch: `1.0.0` → `1.0.1` |
| something **added**: a field, a JSON key, an option, a command, a canary type, a source, a locale | minor: `1.0.0` → `1.1.0` |
| something covered above **removed, renamed or given a different meaning** | major: `1.x` → `2.0.0` |

Before a covered name or option is removed, it is **deprecated** in a minor
release - it keeps working and says it is going away - and removed only in the
next major release. A history line whose meaning changes gets a new `schema`
number, and that is a major release too.

Before 1.0 (`0.x`), minor releases could break things; the changelog says
where they did.

## Third-party plugins

A package outside this repository ships a canary type or a check source by
declaring an entry point. Installing the package is enough; nothing here
needs to change:

```toml
# pyproject.toml of your package
[project.entry-points."stille_hunter.sources"]
my_source = "my_package.my_source"      # a module whose class is @register'ed

[project.entry-points."stille_hunter.types"]
my_type = "my_package.my_type"          # a module whose class is @register_type'd
```

A plugin that fails to load is reported as a warning and skipped; it never
stops the others. The project's limits apply to every plugin - see
[plugin-guide.md](plugin-guide.md).
