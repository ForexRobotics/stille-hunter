# Changelog

All notable changes to stille-hunter are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
While the version is `0.x`, minor bumps may include breaking changes; see
[RELEASING.md](RELEASING.md).

## [Unreleased]

### Added
- Documentation (#19): a user guide (`docs/user-guide.md`) covering every
  command, option, source, notification setting and config section, and a
  plugin author guide (`docs/plugin-guide.md`) for canary types and check
  sources - the contracts, how plugins are found (packages and entry points),
  testing, and the project's limits (read-only, search-only, self-contained,
  never downloading or keeping leaked data). The README links all guides.
  Tests check that every CLI option appears in the user guide and every
  contract member in the plugin guide, and the guide's example plugins run.
- The public API is declared stable from 1.0 (#17): `docs/stability.md`
  lists what is covered - the ledger format, the `CanaryType` /
  `CheckSource` contracts, the CLI and its exit codes, the JSON outputs and
  the config sections - and how each kind of change is versioned (additions
  minor, removals and changed meanings major, with a deprecation first).
- Compatibility tests: ledgers generated by the code of every earlier release
  (0.1.0 - 0.6.0) are kept under `tests/compat/ledgers/` and must keep
  loading, keep their markers and work with `inbox` and `ledger`; contract
  tests pin the plugin interfaces and JSON shapes. `tools/compat_fixtures.py`
  adds the fixtures for each new release (see RELEASING.md).
- Third-party plugins: canary types and check sources are also discovered
  through the entry-point groups `stille_hunter.types` and
  `stille_hunter.sources`, so a separate package can ship one. A plugin that
  fails to load is reported and skipped.
- Traditional Chinese (Taiwan) locale for `member` and `db_dump` records:
  `--locale tw`, also accepted as `--locale zh-TW` (#18). Names in
  characters with passport-style romanization for email and user id,
  addresses with the district's 3-digit postal code, 09xx-xxx-xxx mobile
  numbers and a Taiwanese mail-domain mix; `db_dump` notes in Traditional
  Chinese.

## [0.6.0] - 2026-11-25

### Added
- Ledger management (#15): `stille-hunter ledger list` (canaries per seed tag:
  active, retired, types, inbox count, table, dates - counts only, never
  values), `ledger retire --tag/--id [--reason]` (stamps `retired_at`; `check`
  and `inbox` skip retired canaries) and `ledger rotate --tag --out [generate
  options]` (generates a replacement batch of the same type and size, keeping
  its locale, inbox domain (and its share of the batch) and table,
  appends it, then retires the old one;
  nothing is retired if generating fails). Ledgers are rewritten atomically
  and keep their permissions. `history --ledger` marks retired canaries.
- Ledger rows record the canary `type`; older rows have it inferred from
  their markers. New optional fields `retired_at` and `retired_reason`.
- Hit history across runs (#16). `check --history PATH` (and `inbox
  --history PATH`) appends one JSON line per run - when, version, ledgers,
  each source's outcome, and the hits (canary, marker kind, source, where,
  when) - built from the run report and, like it, **without canary values**;
  the file is created mode 0600. `stille-hunter history PATH [--days N]
  [--json]` summarises it: runs and failures per source, hits per seed tag
  and per source, and per canary its first and last sighting and whether it
  is new in the period.

### Changed
- `check` treats the ledger's bookkeeping fields (`type`, `table`,
  `retired_at`, `retired_reason`) as context, never as searchable markers.
  `table` was previously passed to sources as an extra marker (none searched
  it).

## [0.5.1] - 2026-11-25

### Added
- `stille-hunter inbox` (#12): match mail received on your catch-all against
  the ledger, from an mbox, a Maildir or an IMAP mailbox. Reads recipient
  headers only (To, Cc, Delivered-To, X-Original-To, Envelope-To) plus Date
  and From; IMAP is opened read-only and read with `BODY.PEEK`, so nothing is
  fetched beyond headers or marked as read. Reports per canary: message count,
  first and last date, sender domains. Prints, reports and notifies like
  `check`; the mailbox can live under `"inbox"` in the config, and the IMAP
  password can come from `STILLE_IMAP_PASSWORD`.
- `inbox` check source: the same matching inside `check --sources ...,inbox
  --include-inbox`.
- Guide: setting up a catch-all for inbox detection - choosing the domain,
  DNS (MX, plus SPF/DMARC so nobody can send as it), self-hosted Postfix and
  hosted providers (#13): `docs/inbox.md`.
- German locale for `member` and `db_dump` records: `--locale de` (#14).
  German names (spelled out in ASCII for email and user id: ü -> ue,
  ß -> ss), street addresses with a postcode that fits the city, German mobile
  numbers and a German mail-domain mix; `db_dump` notes are in German.

## [0.4.0] - 2026-11-18

### Added
- `check --report PATH` writes a report of the run, as one self-contained
  HTML page (light and dark) or JSON, by extension; repeatable (#28). It shows
  hits without canary values, each source's outcome and coverage, and the
  canaries checked by seed tag and marker. `--report-title` sets its title.
- `check` takes several ledgers and checks them together in one run (one
  notification, one report).
- Sources can describe what a run covered through `CheckSource.stats` (short
  scalar facts, shown as given in reports). `run_check(..., results=[])`
  returns a `SourceResult` per source; its return value is unchanged.

## [0.3.0] - 2026-11-16

### Added
- Database-ready output for any canary type (#20):
  - `--format sql` writes `INSERT` statements (`--dialect mysql|postgres`,
    `--table`); `--format json` writes a JSON array for framework seeders such
    as Laravel's `DB::table()->insert()`.
  - `--columns field=column,...` selects and renames fields to match a schema.
  - `--table` is recorded in the ledger as where the rows were planted.
  - `--ledger-out` writes the ledger to its own path (e.g. private storage),
    so it does not land next to seeded data inside an app.
  - Seeded output never carries anything that marks the rows as canaries.
- Notifications from `check` (#10): a Slack, Discord or generic HTTPS
  webhook and/or email (SMTP, STARTTLS or SSL), configured under `notify` in
  the config file. Sent when a run finds hits, and when a source fails so an
  unattended check cannot break silently (`"on_errors": false` turns that
  off). Messages never include canary values. `--notify-test` sends a test
  message; `--no-notify` skips notifying for one run.
- Guide to running `check` unattended - cron, Windows Task Scheduler, and a
  scheduled GitHub Actions workflow in a private repository - with the config
  and ledgers kept out of any repository (`docs/unattended.md`, #11).
- `db_dump` canary type: plausible table rows with a searchable reference
  code (e.g. `CUS-A3F8C10421`) that also appears in a free-text note; the
  `github` source searches it as `marker` (#20, formerly #4).

### Changed
- `docs/ledger-format.md` documents every type's ledger fields.

## [0.2.0] - 2026-11-16

### Added
- New canary types, all inert and found by searching:
  - `azure_credential` — Azure service-principal client ID, tenant ID and a
    client secret in the current Entra format (#5).
  - `mcp_config` — an MCP `mcpServers` config block for the GitHub or Slack
    server with a fake token; only official `@modelcontextprotocol`
    packages are referenced (#2).
  - `kubeconfig` — a complete kubeconfig with a bootstrap-format token whose
    id is the canary token, a private-address server and a fake CA blob (#3).
- The `github` source also searches `azure_client_id`.
- CI on every pull request and push to `main`: ruff lint, the test suite on
  Python 3.10–3.14, and a DCO sign-off check on pull requests (#7).
- ruff configuration in `pyproject.toml` with an explicitly pinned rule set
  (E, F, W, I, B; line length 100), and ruff in the `dev` extra.
- Publishing to PyPI: pushing a `vX.Y.Z` tag checks the tag against the
  version, runs the tests, publishes with Trusted Publishing (no stored
  token), and creates the GitHub Release from the changelog (#6).
- Releases are announced on Discord when a `DISCORD_WEBHOOK` secret is set:
  version, release notes (trimmed to Discord's limit) and links, with
  mentions disabled.
- Dependabot keeps the pinned GitHub Actions up to date.
- README badges, and PyPI classifiers for supported Python versions.

### Changed
- Minimum supported Python is now 3.10. Python 3.9 reached end of life in
  October 2025 and is no longer available on current CI runners.
- Code tidied to pass the lint rules: sorted imports, shorter lines, a shared
  helper for North American phone numbers, and an unused variable removed.
  No behaviour change.
- GitHub Actions pinned to full commit SHAs and runners pinned to
  `ubuntu-24.04`, so neither can change what CI runs without a review.
- README images and links are absolute URLs, so they also work on PyPI.
- `tools/release.ps1` now stops after pushing the tag; the publish workflow
  creates the GitHub Release once the PyPI upload has succeeded.

### Fixed
- `api_token --provider` help named a non-existent `random` choice; the
  option for mixing providers is `--mix`.
- `tools/release.ps1` read `CHANGELOG.md` in the Windows code page, which
  would have turned non-ASCII characters into mojibake on release; it now
  reads and writes UTF-8 explicitly.

## [0.1.0] - 2026-11-12

First tagged release. A self-contained leak-canary tool: plant realistic fake
records, then find them if they surface in a breach or public leak. Read-only
and search-only — it never touches anyone else's systems.

### Added
- **Canary generator** (`stille-hunter generate`) with a pluggable `CanaryType`
  architecture — add a type by dropping a module in `stille_hunter/types/`.
  - `member` — full fake member records: locale-consistent names, addresses,
    phones and email domains (`--locale jp|us|gb|ca`), test-BIN card numbers
    that can never be charged, no CVV or national IDs, adults only, with a
    unique token woven through email / user id / password hash.
  - `aws_key` — inert AWS access-key pairs (`AKIA...`), token embedded in the
    tail so they can never collide with a real key.
  - `api_token` — inert service tokens shaped like GitHub / OpenAI / Stripe /
    Slack / generic credentials (`--provider`, `--mix`) (issue #1).
- **Leak checker** (`stille-hunter check`) with a pluggable `CheckSource`
  architecture and a secret ledger mapping each token back to where it was
  planted.
  - `hibp` — looks canary emails up in Have I Been Pwned breaches.
  - `github` — searches public code on GitHub for leaked secret markers
    (keys, tokens, hashes).
  - `null` — reference stub.
  - `Canary.extra` carries type-specific markers so non-member canaries
    (aws_key, api_token, ...) are searchable.
- Two detection paths: **inbox** (catch-all mail on a self-domain) and
  **search** (looking tokens up in leak sources).
- Packaged as an installable `pip`-ready project (src layout, zero runtime
  dependencies, `stille-hunter` CLI entry point), with a pytest suite.
- Apache-2.0 license; DCO sign-off contribution workflow (`DCO`,
  `CONTRIBUTING.md`); project overview and "human-directed, AI-built" diagrams.
